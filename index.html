OOP Definition

Object-Oriented Programming (OOP) is a programming paradigm.

Just like in other areas, there are multiple ways to reach a result. In software development, the same applies.

OOP is the most popular paradigm among developers, as it supports multiple languages and helps structure both development and analysis.

Why is it called Object-Oriented?

An object is a grouping of state and behavior. It represents a real-world or abstract entity relevant to the problem at hand.

Thus, the paradigm brings the real world closer to the digital world.

What languages use OOP?

OOP appeared in the 1970s and is now widely used.

It supports many languages including:

C++, C#, Java, Object Pascal, VB.NET, Objective-C, Python, Ruby

It's rare to find a language that doesn’t support OOP.

The two main concepts of OOP are classes and objects. From them, we derive important principles like encapsulation, inheritance, polymorphism, and abstraction.

The Pillars of OOP

Encapsulation:

Encapsulation hides the internal workings of a class. For example, a car accelerates when you push the pedal, but you don’t need to know how it works inside — just that it does.

In OOP, we make methods and attributes private to prevent unintended changes and ensure clean, secure data handling.

This avoids scope leaks and makes it easier to manage state in complex systems.

Inheritance:

Inheritance allows a class to derive from another. For example, a "Honda Fit WR-V" inherits from "Honda Fit" but adds off-road capabilities.

This lets developers reuse and extend existing code efficiently, establishing parent-child relationships between classes.

Polymorphism:

Polymorphism allows objects to use the same method name but with different implementations. For instance, both a motorcycle and a car might have a startEngine() method, but each behaves differently.

It enables flexibility and consistency across different types of objects.

Abstraction:

Abstraction focuses on the essential features of an object, hiding irrelevant details. To define an object, we specify:

1. Identity: a unique name (often within a package or namespace).

2. Properties: attributes like size, color, or age.

3. Methods: actions the object can perform, like bark() for a dog or turnOn() for a lamp.
